## 현재 통신에 쓰는 정보 전부 (CTF 서버 코드 기준, 26.09.10)

### 공통 규칙

Redis Stream 메시지는 문자열 맵으로, 중첩 객체를 못 싣는다.
숫자도 문자열로 오간다 — userId는 "7"로 보내고 CTF 서버가 ParseInt한다.

CTF 서버는 자기가 아는 키만 읽는다. 모르는 키가 더 있어도 무시하므로 필드 추가는 안전하다.
반대로 필수 필드가 빠지면 파싱이 실패하고, 그 메시지는 재시도 없이 바로 dead-letter로 간다.
(재시도해도 결과가 같기 때문)

상태값은 두 스트림이 같은 값을 쓴다: READY, FAILED


### 지금 쓰는 스트림 4개

ctf:instance:ops              웹 → CTF     인스턴스 생성 요청
ctf:instance:results          CTF → 웹     인스턴스 생성 결과
ctf:challenge:download:ops    웹 → CTF     첨부파일 다운로드 요청
ctf:challenge:download:results  CTF → 웹   presigned URL 결과

컨슈머 그룹은 ctf-provisioners / ctf-download-provisioners.
### 요청 - 공통 머리 (두 요청 모두 같음)

action             필수   지금 값은 CREATE 또는 DOWNLOAD
requestId          필수   결과를 이 값으로 되찾는다
challengeCode      필수   S3 경로 유도에도 쓰인다 (challenges/{code}/{code}.zip)
userId             필수   숫자를 문자열로
requestedAt        필수   지금은 로그로만 쓴다
challengeCategory  선택   WEB같이 인스턴스가 필요한 경우만 띄운다

### 요청 - CREATE에만 추가로 필요한 것

isolationType   필수   SHARED | PER_USER
flagType        필수   STATIC | DYNAMIC

### 요청 - DOWNLOAD에만 추가로 필요한 것

objectKey   선택   웹이 업로드할 때 저장해둔 S3 키. 이미 s3에 저장할 때 ChallengeCode가 prefix로 붙어 있기에
불필요하다.

### 결과 - 공통 (두 결과 모두 같음)

requestId       항상
challengeCode   항상
userId          항상
status          항상   READY | FAILED
message         실패일 때만   실패 사유

### 결과 - 인스턴스에만

host        READY일 때
port        READY일 때   문자열로 보낸다
expiresAt   PER_USER일 때만. RFC3339. SHARED는 만료가 없어서 비어 있다


### 결과 - 다운로드에만

url         READY일 때   presigned URL
expiresAt   READY일 때   URL 만료 시각, RFC3339

빈 값은 아예 키를 안 싣는다. port가 실패했을 때 "0"으로 들어가면 받는 쪽이
0번 포트로 읽을 수 있어서다. 즉 키가 없는 것과 빈 값은 같은 뜻으로 다뤄야 한다.

## 통합 설계할 때 걸리는 것

1. action은 이미 있지만 아무도 안 본다

   두 요청 모두 action을 필수로 받고 있지만, CTF 서버는 그 값으로 분기하지 않는다.
   지금 분기의 기준은 "어느 스트림으로 들어왔나"다.
   하나의 스트림으로 합치면 action이 처음으로 실제 분기 기준이 된다.

   참고로 CTF 서버에는 이미 challengeCategory로 분기하는 라우터가 있다.
   WEB이면 에이전트로 보내고, 아니면 조율자가 직접 끝낸다.
   합칠 때 action과 challengeCategory 중 무엇이 1차 기준인지 정해야 한다.
   (권장: action이 1차. "무엇을 해달라"와 "무슨 분야 문제냐"는 다른 축이다)

2. challengeCategory를 필수로 올려야 한다

   합치면 다운로드 요청에도 이 필드가 실리므로 선택으로 둘 이유가 없어진다.
   다만 웹이 안 보내기 시작하면 CREATE 요청이 인스턴스를 못 띄우고 거절된다.

3. userId를 빼면 PER_USER가 깨진다

   "CTF 서버가 알 필요 없음"이라고 적혀 있는데, 실제로는 지금 이렇게 쓰인다.
   - 컨테이너 이름: PER_USER일 때 ctf-{challengeCode}-u{userId}
   - 도커 라벨: nimda.ctf.user (나중에 인스턴스 목록 조회에 쓴다)
   - 결과에 항상 실어 보낸다 (웹이 자기 요청을 찾는 수단)

   UUID로 대체하려면 그 UUID의 성격을 정해야 한다.
   지금 이름 규칙은 결정적이다. 같은 사용자가 같은 문제를 다시 요청하면 같은 이름이 나오고,
   그래서 기존 인스턴스를 덮어쓴다.
   UUID가 요청마다 새로 발급되는 값이면 요청할 때마다 다른 컨테이너가 생긴다.
   같은 사용자가 버튼을 두 번 누르면 인스턴스가 두 개 뜬다는 뜻이다.

   즉 필요한 것은 "요청 식별자"가 아니라 "사용자+문제 식별자"다.
   requestId와 별개의 값이어야 하고, 같은 사용자·같은 문제면 항상 같아야 한다.

4. 결과 스키마도 같이 합쳐야 한다

   인스턴스 결과는 host/port, 다운로드 결과는 url이다.
   결과 스트림을 하나로 합치면 셋 다 선택 필드가 되고,
   받는 쪽이 무엇으로 구분할지 정해야 한다.
   요청의 action을 결과에도 실어 보내는 게 가장 단순하다. 지금은 안 싣고 있다.

5. requestedAt은 필수인데 쓰이지 않는다

   지금 로그 외에 쓰는 곳이 없다. 필수로 유지할지 선택으로 내릴지 이번에 정하면 좋다.

6. 하위 호환은 없다고 보는 게 맞다

   필드를 더하는 건 안전하지만 필수 필드 이름을 바꾸거나 빼면 CTF 서버 파서가 즉시 실패한다.
   스트림 키까지 바뀌면 양쪽을 동시에 배포해야 한다.
   기존 스트림에 남아 있던 메시지는 새 파서가 못 읽고 전부 dead-letter로 간다.
